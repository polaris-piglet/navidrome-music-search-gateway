# 下一步计划：Navidrome 原生 API 兼容评估

状态：待评估，尚未实现或承诺上线。目标是在保留现有 OpenSubsonic 行为的同时，评估 Feishin 选择 Navidrome 类型时能否使用网关的在线搜索与收藏入库。

## 1. 先核对实际调用链

以明确记录的 Feishin、Navidrome 版本为基线，核对官方源码和经过脱敏的实际请求：登录、会话续期/失效、身份查询、本地与在线搜索、收藏/取消、详情、歌单、封面和媒体播放。形成“接口、认证方式、参数、响应、是否需网关处理”的兼容表；未知项明确标记，不猜测路由。

仅记录接口名、方法、状态码和参数结构，不保存密码、认证请求串、Cookie、令牌、私人曲目或下载地址。

## 2. 设计接口与认证边界

- 区分可直接代理、需要聚合在线候选、需要真实 ID 映射、暂不支持的接口。
- 核对原生会话如何被上游验证，并关联到正确用户及在线功能权限；原生令牌不能未经验证当作 Subsonic 令牌使用。
- 保留原服务授权，不内置管理员凭据、不直接写数据库、不绕过失效或注销。
- 只允许明确的接口范围；管理与网页入口不因兼容登录而默认开放。
- 若必须保存长期凭据或引入高权限桥接，先单列设计取舍，不将其作为无感兼容的默认实现。

## 3. 按完整业务链决定实施

不能只以“登录成功”为完成。需要确认原生模式的搜索能合并在线结果，收藏能进入现有校验和入库流程，正式 ID、取消意图与失败重试能正确衔接；直接代理搜索可能绕过网关功能。

形成可行性结论、最小改动范围及剩余限制后，再确定实现计划。现有 Subsonic/OpenSubsonic 模式作为持续支持与回退入口。

## 4. 验收标准

- 原生模式登录、凭据错误、失效会话与多用户隔离符合上游权限。
- 本地搜索和播放不退化，在线候选搜索、收藏入库、取消及重试不重复发布。
- 原有曲目和歌单不被意外修改，原 Navidrome 入口继续可用。
- Feishin OpenSubsonic 模式和既有客户端做回归检查。
- 文档准确列出支持版本与接口边界；未验收功能不宣称兼容。

## 其他待办

实际无损样例、其他来源和客户端、通用 Docker 镜像启动、其他架构、长期运行及挂载恢复仍需验证。已有文件音质升级和全库语义去重不纳入本轮原生 API 兼容范围。
